- **改动时间**：2026-09（本次）

- **关键改动**：
  1. **新增反馈后台 `admin.html`**：先要口令（默认 `chifan2026`，在 `assets/app.js` 的 `ADMIN_PASS` 里改），进门后是 4 个统计卡（**全部留言 / 今天新增 / 最近一条 / 数据来源**）+ 全部留言列表，支持**一键导出 CSV**和**复制全部**。CSV 带 UTF-8 BOM，用 Excel / WPS 打开中文不乱码，作业直接交这个。页面加了 `noindex`，并且不放进任何导航。

## V3.1 —— 留言只能改删自己的 + 首页开场文案（当前版本）

- **改动时间**：2026-09（本次）
- **本轮目标**：两件事 —— ① 留言板要能分清「谁是谁」：访客**不能**编辑 / 撤回别人的留言，但**能**编辑 / 撤回自己的；② 首页开场保留（用户明确说「那个开场挺好的别删」），只把文字从「嗯，点，线，面。」改成「欢迎来到我的世界」。
- **关键改动**：
  1. **留言归属：本机「钥匙」方案**。每台设备第一次打开网页时，浏览器自己生成一把随机钥匙（`k` + 40 位随机字符）存在本机 `localStorage` 的 `chifan_token` 里；提交留言时随留言一起写进数据库的 `owner_token` 列。
  2. **数据库层面把权限收窄**。`feeds` 表对匿名访客**只开放「插入」**，并且**故意不给** select / update / delete 策略 —— 任何人都无法绕过页面直接读改删数据库。读取、修改、删除全部改走三个 `security definer` 函数：`list_feeds`（只返回钥匙**末 12 位指纹** `fp`，永不返回钥匙本身）、`edit_feed`、`delete_feed`（钥匙对不上直接报错）。前端拿 `fp` 和本机钥匙比对，标出「我的」。
  3. **前端只给「我的」留言渲染按钮**。`initFeedback` 的每条留言改由 `msgNode()` 生成：自己的那条才有「编辑 / 撤回」两个按钮和「我的」标签；**别人的连按钮容器都不生成**（不是隐藏，是不存在）。
  4. **行内编辑 + 撤回**。点「编辑」→ 该条留言原地变成输入框 + 「保存 / 取消」；保存后文字真的更新，并多一个「已编辑」标记；点「撤回」→ 二次确认后删除。提交按钮加了防连点（提交期间自动禁用再恢复）。
  5. **新增留言列表样式**：自己的留言左侧一条浅色竖线（`.mine`）、「我的」/「已编辑」小标签、操作按钮（含悬停态）、行内输入框、时间右对齐。
  6. **首页开场改文案**：`嗯，点，线，面。` → 两行「欢迎来到」「我的世界」+ 英文副标 `WELCOME TO MY WORLD.`；因为两行字比原来短，字号从 `clamp(45px,10.5vw,150px)` 补偿性上调到 `clamp(54px,12.5vw,190px)`，行高 `.94`→`.96`、字距 `-.02em`→`-.01em` 微调。**开场动画节奏（逐行浮现 → 整屏上滑）保持原样没动**。
  7. **说明书同步**：`docs/supabase-setup.md` 按新权限整体重写 —— 加了「这套留言权限是怎么设计的」说明、第二步 SQL 换成含三个函数的完整脚本、第三步改成要确认函数存在、第六步加了「验证权限」的 4 步、「私密模式」从删表策略改成 `revoke execute on function list_feeds`、排错表补了函数缺失和钥匙对不上两类。
  8. **顺手堵掉一个真漏洞**：`admin.html` 的口令门页面上原来**直接把默认口令印在页面上**（写着「默认口令是 chifan2026」），网站一发布等于门锁透明，谁打开后台页都看得见 —— 已把这句提示删掉，只留「这里是站主本人的留言后台，请输入口令进入」；同时把 `ADMIN_PASS` 的默认值换成了只有自己知道的口令。
- **验证**（无头浏览器 DOM 断言，不是靠肉眼看截图）：
  - **自己的留言全流程**：提交 → 出现「我的」标签 + 2 个按钮 → 点「编辑」变成输入框 → 保存后文字真的改了、出现「已编辑」 → 点「撤回」确认后列表回到 0 条。
  - **混排归属**：造一条「别人」的留言 + 提交一条自己的 → 列表 2 条，**别人的那一块按钮数 = 0**（连 `.ops` 容器都没有）、自己的那一块有按钮 → 归属判定正确。
  - **首页开场**：`#intro` 存在、`.i-line` 数量 = 2、文字「欢迎来到 / 我的世界」、英文副标 `WELCOME TO MY WORLD.`、第一行宽 698px（视口 1410px）**不溢出**、逐行浮现的 class 正常加上、播完自动滑出视口（`top = -813`）。
- **遗留**：Supabase 的 `SUPABASE_URL` / `SUPABASE_ANON_KEY` 还是占位符，所以现在仍然跑**本地演示模式**；**新 SQL（含三个函数）需要在 Supabase 的 SQL Editor 里跑一遍**，云端的权限设计才算真正生效。⚠️ 注意：**必须先跑新 SQL 再填 URL/key**，否则反馈页会报「读取留言失败」且列表为空（前端已经在调用还不存在的函数）。
- **下一步**：① 在 Supabase 跑新 SQL；② 填 URL / key；③ 把 `index.html`、`assets/app.js`、`assets/style.css`、`docs/` 更新到 GitHub；④ 用手机打开线上网址提交一条，回电脑确认「手机那条改不了」—— 真机验证权限。

### V3.1 补记 —— Supabase 云端正式闭环（同日完成）

- **本轮完成**：把上面 V3.1 的「遗留 / 下一步」全部做完，留言板**真正跑在云端**了。
- **关键改动**：
  1. **填上云端配置**：`assets/app.js` 的 `SUPABASE_URL` / `SUPABASE_ANON_KEY` 换成真实值（新版 **Publishable key**，`sb_publishable_...`）。
  2. **提交留言改走函数 `add_feed`**。踩到的坑：新版 Publishable key **不是 JWT**、不带 `anon` 角色声明（诊断函数 `whoami()` 显示 `jwt.role=(NOT SET)`），所以 `to anon` 的 insert 策略匹配不到它，**直连 insert 会报 `42501 / new row violates row-level security policy`**。解决办法是把写入也放进 `security definer` 函数，四个函数统一入口。SQL 见 `outputs/supabase-add-feed.sql`。
  3. **修掉一个会让整站静默失效的隐患**：站点原来从 `cdn.jsdelivr.net` 加载 supabase-js，实测该域名在本机网络下**连接被重置**（`WinError 10054`），无头浏览器拿不到 `window.supabase`，页面就**静默退回本地演示模式** —— 真实访客也会遇到同样问题。已把库**下载进仓库**（`assets/supabase.js`，218 KB，UMD 版），7 个页面全部改成 `<script src="assets/supabase.js"></script>`，**不再依赖任何 CDN**。
  4. **文档同步**：`docs/supabase-setup.md` 补上 `add_feed` 函数、Publishable key 说明、`42501` / `PGRST202` 两条排错，并把 CDN 那条从「换网络重试」改成「改用仓库内文件」。

### V3.2 —— 修好「星点难点」的导航 bug（来自真实使用反馈）

- **触发原因**：把网址给朋友试用后收到反馈 —— 星空里的节点**经常点不到，要对准很久才行**。
- **定位到 3 个叠加问题**（全部在 `assets/app.js` 的星空模块）：
  1. **坐标没换算（最致命）**：命中判定把鼠标事件的**视口坐标**直接拿去和节点的**画布内坐标**比较。只要画布不在视口左上角（页面滚动中，或它上方还压着开场屏），两者就整体错位 —— 错位多少，就偏多少，表现为「明明对着光晕点，就是没反应」。已加 `toLocal()` 做统一换算。
  2. **点击判定太灵敏**：旧代码把每一小段位移**累加**（`moved += |dx| + |dy|`），超过 6px 就当成「你在拖动」并丢弃这次点击。鼠标 / 触控板点一下的手抖就够触发 —— 越是小心翼翼越点不中。已改成计算**按下点到当前点的直线距离**，阈值放宽到 12px。
  3. **节点太小、看不出能点**：节点半径只有 3.4px（屏幕上约 7px 的小点），且要鼠标进入 70px 范围才变手型，视觉点和手感区差 10 倍。已把半径加到 5.2，并给每个节点加**常驻细圆环**，让人一眼看出「这里可以点」。
- **顺带补上手机端**：原来只监听鼠标事件，手机上**完全拖不动**星空。已增加 `touchstart / touchmove / touchend`：单指拖 = 平移星空，轻点 = 进入页面（并用 `preventDefault()` 避免触发两次跳转）。
- **验证**（新增回归脚本 `.deepworks/tmp/e2e_star.js`，用 iframe 加载首页后派发合成鼠标事件）：
  - 干净点击 → 跳转 ✅
  - **手抖点击（位移约 4px）→ 跳转 ✅ —— 这一条在旧代码下必然失败**
  - 真拖动（位移 150px）→ 不跳转 ✅（确认拖动探索仍然正常）
  - 7 个节点全部命中，悬停提示正确（`进入：about.html` 等）✅
  - 7 个页面回归加载全部正常 ✅
- **影响文件**：`assets/app.js`（33320 → 35309 字节）。

**上线排查中踩到的一个真问题**

部署前发现线上留言接口整体不可用。排查步骤：

1. 用 4 个独立 DNS（阿里 / 腾讯 / Google / 本地电信）交叉查询项目域名，
   全部返回 `NXDOMAIN`（域名不存在）；
2. 同时做了两组**对照**：`supabase.co` 主域解析正常；随便编一个不存在的项目也是 `NXDOMAIN`
   —— 由此排除「本机 DNS 故障」这一可能；
3. 结论：项目被 Supabase **自动暂停**（免费版长期无活动），暂停后域名记录被移除；
4. 恢复项目后，域名解析恢复，`list_feeds` 返回 200，**16 条留言一条不少**。

**教训**：免费版的暂停是「静默」的——前端只会表现为「连不上服务器」，
很容易被误判成代码回归。以后遇到同类现象，**先查 DNS，再查代码**。

**给批改期的提醒**：免费项目约 1 周无访问会再次暂停。
建议批改期每周打开一次站点（或进控制台看一眼），避免老师点开时打不开。
