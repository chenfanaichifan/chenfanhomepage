## V2 —— 参考作品集站改版 + 星空

- **改动时间**：2026-09（本次）
- **参考**：https://seunghyuk.com/ （**只参考设计思路与效果，未复制任何代码或素材**）
- **本轮目标**：把主页改成参考站那种「平面设计师作品集」的高级感，并加上星空；点的星点要能真的跳进功能页面。
- **关键改动**：
  1. **整站拆成 6 个真页面**：`index.html`（星空导航首页）+ `about.html` / `projects.html` / `twin.html` / `feedback.html` / `contact.html`；样式与脚本抽成共用文件 `assets/style.css`、`assets/app.js`。
  2. **开场动画**：深色半调网点背景 + 超粗字体逐行浮现「嗯，点，线，面。」（对应参考站 WELL, DOTS, LINES, PLANES.），随后整屏向上滑出。
  3. **星空节点网络**（纯原生 Canvas 手写，无第三方库）：星点漂浮，7 个节点用线连成星座（关于我 / 项目 / 技能 / 经历 / 反馈 / 分身 / 联系），鼠标靠近会高亮并显示「进入 →」，**可以拖动探索**（拖动过的不算点击），**点节点 = 浏览器整页跳转**（`location.href` 载入对应页面，不是同页滚动）；标签靠近右边缘会自动翻到左边，保证不出画布。
  4. **星空加强**：星点约 600 颗，多层视差（滚动 / 拖动时远近的星速度不同），按大小与颜色分层（白 / 冷蓝 / 暖黄），大星带柔光，逐颗闪烁，并新增**流星**划过；首页 Hero、星空导航区、以及各功能页页头**全部铺上星空层**。
  5. **首页叙事**：开场动画 → 浅色 Hero（超大「HAOHAO / 好好吃饭」+ 自我介绍 + 联系方式）→ 深色星空导航区（「点点连成线，线连成面。」）→「INDEX — 全部页面」索引卡片 → 页脚。
  6. **5 个功能页统一版式**：面包屑（星空首页 / 01 / ABOUT …）+ 巨型标题 + 内容区 + 「← 返回星空首页」+ 页面互跳卡片 + 页脚；深浅配色与首页一致。
  7. **细节**：十字准星自定义光标、隐藏滚动条、禁用正文选中、顶栏在深浅场景之间自动反色、半调网点纹理由 CSS 生成、`prefers-reduced-motion` 时关闭动效、响应式（900 / 680 / 560px 断点）。
  8. **内容与功能保持不变**：数字分身问答、反馈留言（可选匿名）、Supabase 云端接口与本地回退、联系方式（QQ 2350776866 / 微信 13807430106）逻辑未动。
- **版权说明**：全程只看设计思路与效果，代码 100% 原创手写（含 Canvas 星空），未复制参考站任何代码或素材；字体为开源 OFL 授权（Google Fonts）。
- **验证**：脚本标签成对、大括号 / 小括号平衡；所有链接与锚点存在、关键元素 id 齐全、6 页顶栏一致；用无头浏览器对 6 个页面逐屏截图自查，并用脚本读取真实画布尺寸核对 7 个星空节点是否都在可视区内。

## V3 —— 反馈功能真正能用：能收到、能存下、能查到（当前版本）

- **改动时间**：2026-09（本次）
- **本轮目标**：把「反馈意见」从「能演示」变成「真的能收到」——访客在前端提交 → 数据存进后台 → 发布到 GitHub → 我能收到、能存下、能查到。
- **关键改动**：
  1. **新增反馈后台 `admin.html`**：先要口令（默认 `chifan2026`，在 `assets/app.js` 的 `ADMIN_PASS` 里改），进门后是 4 个统计卡（**全部留言 / 今天新增 / 最近一条 / 数据来源**）+ 全部留言列表，支持**一键导出 CSV**和**复制全部**。CSV 带 UTF-8 BOM，用 Excel / WPS 打开中文不乱码，作业直接交这个。页面加了 `noindex`，并且不放进任何导航。
  2. **反馈页交互补全**：提交按钮下方新增状态条，明确显示「正在提交…」「已收到，谢谢你的反馈！」「提交失败：具体原因」，提交期间按钮会禁用再恢复；留言列表上方显示「已收到 N 条留言」，本地演示模式会额外标注「（本地演示模式）」；每条留言补上**提交时间**。
  3. **建表 SQL 改成能一次跑通**：`drop table if exists` + `not null default now()` 的完整脚本，`feeds` / `twin` 两张表和 RLS 策略一次跑完。文档里补了**排错对照表**（`0A000` 默认表达式报错、表已存在、SQL 只跑了一半、RLS 拦截、一直显示本地演示模式等）和**私密模式**（让留言不公开）的说明。
  4. **新增发布指南 `docs/github-pages.md`**：这台电脑没装 git，所以走 **GitHub 网页拖拽上传 → Settings → Pages** 的零命令行路线，写清了三个最常踩的坑（只传了 HTML 忘了 `assets/` 文件夹、文件夹套层导致 404、仓库必须是 Public）和三条安全红线。
  5. **顺手修掉一个真实缺陷**：本地演示模式下 `fetchFeeds` 直接用内存里的数据，导致后台的「刷新」按钮点了没反应；改成每次都从 localStorage 重新读一次。
  6. **统计卡排版**：「最近一条」原来显示完整年份会在卡片里折行，改成 `09-17 16:53` 短格式并单独调小字号。
- **数据流**：访客浏览器 → Supabase REST API → 数据库 `feeds` 表；我的后台 `admin.html` → 读同一张表 → 统计 / 列表 / 导出 CSV；数字分身则读 `twin` 表（为空时用页内置问答）。
- **验证**：脚本校验 7 个页面全部通过（标签成对、括号平衡、链接与锚点存在、关键元素 id 齐全、顶栏一致）；再用无头浏览器**真实模拟走一遍**：输错口令 → 被挡住 → 输对口令 → 进入后台 → 提交一条留言 → 状态条变绿、计数 +1、列表回显、写入本地存储、按钮恢复可用 → 后台读到 3 条数据（统计 3 / 今日 2 / 最近一条正确）→ 导出 CSV 首字节确认为 `EF BB BF`。新页面逐屏截图目视确认无错位。
- **遗留**：Supabase 的 `SUPABASE_URL` / `SUPABASE_ANON_KEY` 还是占位符，所以现在跑的是本地演示模式；填好并发布后，这一步才算真正闭环（见 `docs/supabase-setup.md`）。
- **下一步（V4 可做）**：填好 Supabase 配置、发布公开链接、邀请 3–5 位同学留下真实反馈；之后再考虑给后台加「有新留言时提醒我」。

## 提问｜自己补充数字分身问答

想加问答，两种方式任选：

- **方式 A（本地，改动最少）**：直接改 `assets/app.js` 里的 `DEFAULT_TWIN` 数组，加一条即可。
- **方式 B（上云）**：在 Supabase 的 `twin` 表里 `insert` 一条（`keywords` + `answer`），页面会自动读取。

> 提醒：现在整站是 6 个前台页面 + 1 个后台页（`admin.html`）共用 `assets/` 里的样式和脚本，改样式改 `assets/style.css`、改逻辑改 `assets/app.js`，不用每个页面都改。
> 后台口令也在 `assets/app.js` 顶部的 `ADMIN_PASS`，记得改成你自己的。
