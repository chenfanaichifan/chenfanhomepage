# Supabase 后台接入说明（V3 反馈功能）

这个网站有两条数据链：

| 功能 | 走向 | 表 |
|---|---|---|
| 「反馈意见」留言 | 访客提交 → 存进 Supabase → 你和访客都能看到 | `feeds` |
| 「数字分身」问答 | 页面从 Supabase 读取问答库 | `twin` |
| 「反馈后台」admin.html | 只有你知道口令，集中看留言、导出 CSV | 读 `feeds` |

> **没配置也不会白屏**：未配置时页面自动进入「本地演示模式」，留言存在浏览器 localStorage，功能能演示，但不会跨设备同步、别人也看不到。配置好之后才会真正「收到」。

---

## 第一步：建项目

1. 打开 https://supabase.com ，用邮箱或 GitHub 注册 / 登录。
2. 点 **New Project**：名字随便起（例如 `chifan-homepage`），数据库密码点 **Generate a password** 并**存下来**，区域选 **Southeast Asia (Singapore)**。
3. 等 1 分钟左右，等它从 "Setting up project" 变成正常界面。

## 第二步：建表（复制粘贴，一次跑完）

左侧点 **SQL Editor**（图标像 `</>`），点 **New query**，把下面**一整段**粘进去，点右下角 **Run**（或按 `Ctrl+Enter`）。

```sql
-- ========= 1. 反馈留言表 =========
drop table if exists public.feeds cascade;

create table public.feeds (
  id         bigint generated by default as identity primary key,
  name       text not null default '',
  text       text not null,
  anon       boolean not null default false,
  created_at timestamptz not null default now()
);

alter table public.feeds enable row level security;

drop policy if exists "feeds public insert" on public.feeds;
drop policy if exists "feeds public select" on public.feeds;

create policy "feeds public insert" on public.feeds
  for insert to anon with check (true);

create policy "feeds public select" on public.feeds
  for select to anon using (true);


-- ========= 2. 数字分身问答表 =========
drop table if exists public.twin cascade;

create table public.twin (
  id         bigint generated by default as identity primary key,
  keywords   text[] not null,        -- 触发关键词，如 {你好,自我介绍}
  answer     text not null,          -- 回答内容
  created_at timestamptz not null default now()
);

alter table public.twin enable row level security;

drop policy if exists "twin public select" on public.twin;

create policy "twin public select" on public.twin
  for select to anon using (true);
```

看到下方出现 **Success. No rows returned** 就是成功了。

> ⚠️ `drop table if exists` 会**清空这两张表里已有的数据**。如果之后表里已经有真实留言、你只想补策略，就只运行 `alter table` / `create policy` 那几行，别跑 `drop`。

## 第三步：确认策略生效

左侧 **Table Editor** → 能看到 `feeds`、`twin` 两张表。
再点左侧 **Authentication → Policies**，`feeds` 应该有 2 条策略、`twin` 有 1 条。

## 第四步：往「数字分身」表塞问答（可选）

在 **SQL Editor** 里 Run：

```sql
insert into public.twin (keywords, answer) values
  (array['你是谁','自我介绍','hello','你好'], '我是好好吃饭，真名陈帆，一个相信天天进步的人。'),
  (array['想赢','口号','slogan'], '「想赢的人是不会笑的」——认真的时候我不开玩笑。'),
  (array['联系方式','qq','微信','联系'], 'QQ：2350776866；微信：13807430106。'),
  (array['鼓励','加油','坚持'], '保持初心，天天开心，保持向上。加油！');
```

> 云端 `twin` 表有数据时页面**优先用云端问答**；表为空就用页面内置的默认问答（`assets/app.js` 里的 `DEFAULT_TWIN`），所以这一步不做也完全能用。

## 第五步：把 URL 和 key 填进代码

1. Supabase 左侧 **Project Settings**（齿轮）→ **API**。
2. 复制 **Project URL**，形如 `https://abcdefgh.supabase.co`。
3. 在 **Project API keys** 里复制 **anon / public** 那一串（很长，`eyJ...` 开头）。
   ⚠️ 只复制 **anon public**，**绝对不要**复制 `service_role`。
4. 打开项目里的 `assets/app.js`，最上面找到这两行，**只替换引号里的内容**：

```js
const SUPABASE_URL = "在这里粘贴你的Supabase项目URL";
const SUPABASE_ANON_KEY = "在这里粘贴你的anon_public_key";
```

改成（示例）：

```js
const SUPABASE_URL = "https://abcdefgh.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.很长很长很长";
```

5. 保存文件，刷新网页。

## 第六步：验证真的通了

1. 打开 `feedback.html`，随便写一条留言、点「提交留言」。
2. 按钮下方出现绿色 **已收到，谢谢你的反馈！** = 前端通了。
3. 打开 `admin.html`，输入口令（默认 `chifan2026`），如果能看到刚才那条留言、右上「数据来源」显示 **云端 Supabase** = 整条链路通了。
4. 也可以回 Supabase **Table Editor → feeds** 里直接看到数据。

**判断标记**：在 `feedback.html` 留言列表上方，看到「已收到 N 条留言」后面**没有**「（本地演示模式）」这几个字，就是真的在走云端。

## 常用排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `0A000: 无法在默认表达式中使用列引用` | 你多半不在 Supabase 的 SQL Editor 里，而是在别的数据库工具（Navicat / DBeaver / 本地 Postgres）里跑；或是在 Table Editor 的建列弹窗里填了 `now()` | 确认地址栏是 `supabase.com/dashboard/project/_/sql/new`，用上面那段完整 SQL 重跑 |
| `42P07: relation "feeds" already exists` | 表已存在 | 先跑 `drop table if exists public.feeds cascade;` |
| `42P01: relation does not exist` | SQL 只跑了一半 | 全选整段 SQL 再点 Run（**没选中时 Run 跑全部，选中了就只跑选中的**） |
| `42501: permission denied` | 用的 key 不对 | 换成 **anon public** key，别用 service_role |
| 留言提交后没进后台，列表也看不到 | RLS 策略没建成功 | 重跑 `create policy` 那几行，检查 Authentication → Policies |
| `new row violates row-level security policy` | 只有 select 策略、没有 insert 策略 | 补 `feeds public insert` 那条策略 |
| 网页一直显示「（本地演示模式）」 | `assets/app.js` 里还是占位符，或 URL 没以 `https://` 开头 | 检查 `SUPABASE_URL` 是否以 `https://` 开头、key 是否完整 |
| 打开页面白屏 | CDN 被墙 / 断网（Supabase 的 JS 走 jsdelivr） | 换网络重试；代码本身不依赖 CDN 也能回退本地模式 |

## 私密模式（让留言不公开）

默认配置里 `feeds` 允许匿名**读取**，所以留言会公开显示在「反馈意见」页——这像个留言板，适合展示。

如果你想让留言**只有自己能看**：

```sql
-- 删掉公开读取策略
drop policy if exists "feeds public select" on public.feeds;
```

这样只会断掉前端读取列表的能力：
- `feedback.html` 提交后仍然成功（insert 保留），只是列表读不出来；
- `admin.html` 也是用同一个 anon key 读的，同样读不出来；
- 此时请改用 **Supabase → Table Editor → feeds** 直接看留言、右上角 **Export** 导出 CSV。

> 更进阶的做法是加一个带密码参数的 `security definer` 数据库函数（RPC），让后台页面凭密码调用。课程作业阶段不必要，先让数据跑通最重要。

## 数据流回顾（对应课程阶段三）

```
访客浏览器 ──提交留言──→ Supabase REST API ──写入──→ 数据库 feeds 表
访客浏览器 ──读取留言──→ Supabase REST API ──读取──→ 渲染「反馈意见」页
你自己的后台 admin.html ──口令进门──→ 读取 feeds → 统计 / 列表 / 导出 CSV
访客提问 ──→ 页面匹配 twin 表（或内置问答）──→ 数字分身回答
```

**安全提醒**：`anon public` key 放在前端是**正常且设计如此**的，它的权限完全由 RLS 策略决定。**`service_role` / secret key 绝不能出现在前端代码或 GitHub 仓库里**。收集信息只保留必要字段（称呼、内容），不要收集手机号等敏感信息。
